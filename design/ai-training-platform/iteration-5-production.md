## 1. 0–90 秒入场体验

### 1.1 设计目标

用户从扫码到看到"Node 1 等待中"，应该 < 90 秒，且**不需要**：
- 注册账号
- 下载 App
- 加微信群
- 关注公众号

### 1.3 引导卡片不是教程

强制完整阅读教程是反人性的。引导卡片用：
- **可滑过**（点 X 跳过）
- **进度可见**（"1/3"）
- **不是模态**（背景候场厅依然活跃可见）

## 2. 会前 / 会中 / 会后三段式

### 2.1 会前 48 小时

```
T-48h  报名成功
       自动邮件 1：欢迎信 + 工具准备清单
       自动邮件 2：日历邀请（.ics）

T-24h  邮件 3：开课提醒 + 加入群（仅当事件需要）

T-2h   邮件 4：今天 14:00 见！+ 二维码 + 入场短码

T-15min 推送（如果用户授权）：5 分钟后开始
```

工具准备清单**会前一次性发**，不要求看完才能入场（但完成 5 个核对的人入场后有"准备充分"徽章）。

### 2.2 会中（已在前 4 版覆盖）

略。

### 2.3 会后 7 天

```
T+0      散场即刻
         颁奖典礼界面同步生成 recap 链接
         一键分享 recap 到朋友圈/小红书

T+1h     邮件 1：你的成就单海报 + recap 链接
         随邮件附 20 个节点用过的 AI 工具速查表 PDF
         （这个 PDF 是平台的"长尾资产"）

T+24h    邮件 2：你最高赞的 3 个作品 + 别人对它的评价
         + 你点赞最多的 3 个作品

T+72h    邮件 3：1 周练习挑战 — "再用一次第 20 关的工作流，
         解决一个真实痛点"
         + 上传分享 → 进入"校友墙"

T+7d     邮件 4：下期预告 + 老学员 80 折 + 推荐有礼
```

设计要点：
- **不每天发** — 避免被标记为骚扰
- **每封都有具体价值** — 不是营销文案
- **推荐有礼是天然增长引擎** — 推荐者下次半价，被推荐人首次免费

## 3. 主持人运营 SOP

### 3.1 主持人的 8 个动作

按时间顺序：

```
T-7d    确认主题 + 阅读教研发的"主持人脚本"
T-48h   收到学员名单 + 工具清单完成度（已发邮件）
T-24h   彩排：进主持人台试操作 5 个核心按钮
T-30min 进场，与助教对接
T-5min  开声音、开摄像头（如直播）、暖场
T=0     主持人开场 → 进入 FSM
T+0     主持人结束 → 会议结束语
T+1d    收到学员反馈数据 + NPS 报告
```

### 3.2 主持人脚本模板

每场培训有教研生成的"主持人脚本"，关键节奏点配台词：

```
=== Node 1 之前 (T=2:30) ===
开场白（2 分钟）：
  「欢迎大家来到 LightningClass。
   接下来 2 小时，我们要一起完成 20 个 AI 挑战。
   不要紧张，第一关是给你认识自己用的。
   AI 不是要替代你，是要让你成为'有 AI 加持'的你。」

按 [公布题目]

=== Node 1 期间 ===
观察看板：
  - 30 秒：应该 > 50% 进入提交
  - 60 秒：应该 > 80% 已提交
  - 如果 90 秒还有 < 60% 提交：口播
    「Node 1 是热身，记得用一键复制按钮就行。」
  - 105 秒：[关闭提交 & 投票]

=== Node 1 揭榜 ===
点评要点：
  - 找一个最有创意的暱称段子
  - 表扬"敢于让 AI 调侃自己"的人
  - 一句话：「你已经做到了 90% 的人做不到的——
              让 AI 服务你，而不是怕它。」

按 [进入下一关]
```

主持人不需要原创，只需"按脚本演 + 自己加风格"。

### 3.3 助教协议

每场配 1-2 名助教，分工：

```
助教 1：群内技术支持
  - 监听学员的"我账号不行""我界面卡了"等问题
  - 共享 ChatGPT Plus 临时账号池
  - 紧急联系工程师

助教 2：投票观察员
  - 监听"投票健康度"看板
  - 如发现可疑共谋（同 IP 多账号、循环互投），通报主持人
  - 必要时主持人按"重置该节点投票"
```

## 4. 商业模型

### 4.1 双轨

**B2C 公开课**

```
定价：单场 99 元 / 200 人
单场收入：~19,800
成本：
  - 主持人：3,000
  - 助教 ×2：1,000
  - 平台费 (Supabase + Vercel)：~200
  - 营销获客：人均 30 = 6,000
毛利：~9,600 / 场（48%）
```

每周 2 场，月毛利 ~76,800。

**B2B 企业团建/培训**

```
定价：4 万 / 场（含定制主题、专属主持人、企业 logo）
单场利润：~28,000
特点：决策周期长（30–90 天），但客单价 20×，复购率高
```

### 4.2 B2B 定制能力

B2B 客户要求"定制主题"——产品该不该接？

V2 的接口已经预留：
- 教研后台可上传企业 logo、定制色板
- 课程节点可替换为客户行业的案例
- 数据可导出为 BI 报表（CSV / Webhook）

但**不**支持私有部署。私有部署是 V3 + 的事。

### 4.3 单元经济测算

每用户 LTV（生命周期价值）：

```
B2C 单次：99 元
复购率（90 天内）：35%（带 80 折）→ 79 元
推荐率：20% 带新人，新人单次 99
LTV 估算：99 + 35% × 79 + 20% × 99 = 146 元
```

CAC（获客成本）：30 元 / 人  →  LTV/CAC = 4.9，健康。

## 5. A/B 实验框架

### 5.1 哪些东西需要 A/B

按"对体验的影响"排序：

| 实验 | 假设 | 优先级 |
| --- | --- | --- |
| Node 1 简化版 vs 完整版 | 简化版完课率 +15% | P0 |
| 中场时长 4min vs 5min | 4min 召回率 +8% | P0 |
| 投票数 3 vs 5 | 5 票更分散，但决策疲劳 +5% | P1 |
| 入场强制工具体检 vs 选择性 | 强制后完课 +20% | P1 |
| 颁奖典礼时长 6min vs 4min | 6min NPS +0.3 | P2 |
| 节点 7 难度 ★★★ vs ★★ | 更易完成 vs 更有挑战 | P2 |

### 5.2 实验设施

```sql
ALTER TABLE training_events ADD COLUMN experiments jsonb DEFAULT '{}';
-- e.g., { "node1_variant": "simple", "interval_min": 4 }
```

实验分配在创建事件时确定：相同实验组的整场都用同一组配置。**不在事件内做 per-user 切分**——多人同步场景下用户能互相看到，per-user 切分会暴露 inconsistency。

### 5.3 度量指标

每个实验跟踪 3 个核心指标：

```
完课率 = 完成 Node 20 的人数 / 入场人数
满意度 = 散场 NPS 调查（"愿意推荐给朋友吗"）
传播率 = 7 天内 recap 链接被点击的次数 / 学员数
```

样本量：每个 variant 至少 6 场 × 50 人 = 300 人，用 frequentist t-test。

## 6. WCAG 2.1 AA 完整适配

### 6.1 关键检查项

| 项 | 当前状态 | V5 目标 |
| --- | --- | --- |
| 文字对比度 ≥ 4.5:1 | 已校（V2） | 维持 |
| 大字 ≥ 3:1 | 已校（V2） | 维持 |
| 焦点可见 | 部分组件 | **全部组件** |
| 键盘可达 | 主要操作 | **包括投票、双屏切换** |
| 屏幕阅读器 | 部分 aria | **完整 aria + live region** |
| 自动播放控制 | 无 | **颁奖烟花可关** |
| 无障碍倒计时 | 视觉 | **音频提示 + 可暂停** |
| 错误提示 | 桃橙色 | **不仅靠颜色，要文字** |
| 视频字幕 | N/A | **会后 recap 视频必带字幕** |

### 6.2 听障友好

- 颁奖烟花的"咚咚咚"鼓点用视觉化（屏幕震动 +大字"鼓点 1!"）

- 上榜不仅是金色描边，还有 🏆 图标 + "TOP 3" 文字

### 6.4 老年友好

- 字号默认 16px，UI 设置可一键放大到 18px
- 重要按钮目标 ≥ 44×44 pt

### 7.1 阶段拆分

```

W03–W06  MVP 开发 (V1.0)
         ├─ W3: 数据库 schema + auth + Realtime POC
         ├─ W4: 学员端核心循环（入场→提交→投票→揭榜）
         ├─ W5: 主持人台 + FSM 完整链路
         └─ W6: 颁奖典礼 + 奖章生成
W07      内测 — 公司内 30 人闭门测试
W08      Bug 修复 + 部分 V2 体验项
W09      公测 — 50 人付费首场
W10      迭代修正 + 上 V3 游戏化经济
W11      规模化 — 100 人场 × 2
W12      公开发售 + 启动会前/会后流
```

### 7.2 每周交付节奏

```
周一：本周目标对齐 + 本周设计评审（如有）
周二–周四：开发 + 每日 standup
周五：dogfood 测试 + 周回顾
周末：不工作（除上线日）
```

### 7.3 Go / No-Go 标准

公开发售前必须：

```
✅ 完课率 > 80% (W09 测得)
✅ NPS > 40 (W09–W11 综合)
✅ 0 起 P0 事故（数据丢失、长时宕机）
✅ Realtime 200 并发稳定 30 分钟
✅ 主持人脚本完整 + 至少 3 位主持人完成认证
```

任何一条不达标，延期。

## 8. 成功指标

### 8.1 北极星指标

**P95 NPS（推荐意愿）**

不是平均 NPS，是 P95——因为关键是"是否有一批人愿意主动推荐"。
目标：P95 ≥ 9.0（10 分制）。

### 8.2 关键二级指标

| 指标 | 阶段 | 目标 |
| --- | --- | --- |
| 完课率（完成 Node 20 / 入场） | 全场 | ≥ 80% |
| 节点平均提交率 | 单节点 | ≥ 75% |
| 颁奖到达率（坚持到典礼） | 全场 | ≥ 90% |
| 7 天 recap 分享率 | 会后 | ≥ 25% |
| 90 天复购率（来第二场） | 会后 | ≥ 30% |
| 投票分布 Gini 系数 | 健康度 | 0.3–0.55 |

### 8.3 健康度反向指标

```
任何一场出现以下情况触发复盘：
  - 完课率 < 70%
  - 单节点提交率 < 50%
  - NPS < 5（任何一个）
  - Realtime 失败 > 5 次
  - 主持人台报错 > 3 次
```

## 10. V5 摘要 / 最终设计陈述

### 10.1 LightningClass 的产品定位

> **一个让普通人在两小时内拿到"AI 学徒证"的实时游戏化课堂。**

它不是 LMS、不是 MOOC、不是工具教程，而是一种**集体学习 + 即时反馈 + 可分享成果**的新教学体裁。

### 10.2 我们最重要的 10 个决策

1. **匿名入场** — 没有账号系统，扫码进
2. **双屏配对协议** — 电脑跑 AI，手机看平台
3. **Node 1 是破冰不是教学** — 保证 100% 首次成功
4. **FSM 挂在节点级** — 而非事件级
5. **5+1 主持人按钮 + 按住 1 秒** — 误操作率 0.3%
6. **温柔 streak** — 漏一关不归零
7. **vote_weight 五因子** — 防共谋同时奖励多元
8. **潜水者四级拯救** — 给参与，也给体面退场
9. **奖章是产品种子** — 可下载、带 recap 链接、序列号
10. **会后 7 天四封邮件** — 把单场变成长尾

### 10.3 我们为什么相信它

把"低参与度""单向灌输""缺乏实操"这三个传统培训死结一次性解开的产品形态，市场上还没有。Duolingo 解了语言的死结，Kahoot 解了课堂答题的死结，**LightningClass 要解 AI 实践教学的死结**。

它不会取代你的 Coursera 订阅，但它会成为你 2026 年朋友圈最常出现的"我刚刚拿了 LightningClass 第 X 期金牌"截图来源。

### 10.4 何时承认设计完成

设计永远不"完成"，但当满足以下三条，我们就停止迭代、开始建造：

- ✅ 12 个风险有 12 个对应方案
- ✅ 主持人能跟着 SOP 跑完一场
- ✅ 工程师能按 schema + FSM spec 拍工时

这三条 V5 之后已经满足。**接下来是 12 周冲刺，不是设计了。**

## 11. 致下一个版本（如果有）

- 给企业的"白标 + 私有部署"如何标准化？

但这些都是 12 周冲刺活下来之后再考虑的事。
