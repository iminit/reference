## 1. 设计原则（六条）

这六条不是口号，是后续每个组件、每次评审的"卡尺"。

### 原则 1：**鼓励 > 评判**（Encouragement over Judgement）

- 所有"错误"反馈用浅色 + 鼓励文案 + 微动画，**禁用红色错误图标**。
- 投票低分不显示"末位"，只显示"还差 2 票就上榜"。
- 主持人台甚至把"提交失败"叫"提交未抵达"，避免学员的羞耻感被无意识强化。

### 原则 2：**速度 = 反馈**（Latency is Feedback）

- 任何用户动作必须在 100ms 内有视觉响应（即使是 skeleton）。
- 提交成功的"卡片飞上瀑布流"必须先于"服务端确认"播放（乐观更新 + 失败回滚）。
- 投票图标在 50ms 内变色，"+1" 数字 200ms 内冒出。

### 原则 3：**同侪存在感**（Social Presence）

- 顶部花名册永远在线，断线 5 秒内不消失（保留头像 + 灰阶）。
- 别人正在打字、正在投票、正在提交，都要有"幽灵动效"——你能感觉到周围有 80 个人。
- "Node X 已有 23 人提交"的数字是实时跳动的，不是刷新出现的。

### 原则 4：**屏幕分工**（Two-Screen Reality）

- 假设 80% 学员一台电脑跑 AI，一部手机看平台。
- 任何长内容（题目、瀑布流）必须在手机上一屏可读。
- 提交可以**电脑端粘贴**也可以**手机端语音输入**，都进入同一个队列。

### 原则 5：**主持人是 DJ**（Host as DJ）

- 主持人控制台的视觉语言对标 OBS Studio / DJ 软件，不是 Excel。
- 5 个核心按钮必须**单手按、肌肉记忆**。
- 实时大屏让主持人**5 秒扫一眼**就知道全局节奏（提交速度、投票活跃度）。

### 原则 6：**可分享性优先**（Designed to be Shared）

- 每个里程碑（拿徽章、上榜、获奖）都生成可下载的 1080×1920 海报。
- 颁奖典礼有"截图最佳时刻"动效，引导用户分享。
- recap 页是公开链接，未登录访客也能看作品集。

## 2. 视觉系统

### 2.1 调性

**关键词**：午后阳光、晨跑、果汁吧、街机厅。
**不是**：考场、Office、银行。

### 2.2 色彩 token

不抄多邻国的绿，因为绿色已经是"学习类 App"的红海。LightningClass 选择**桃橙 + 海蓝**的对撞：

| 角色 | Light | Dark | Hex | 使用场景 |
| --- | --- | --- | --- | --- |
| `accent/peach` | `#FF7A59` | `#FF8A66` | 主操作（CTA、激活态） |
| `accent/sky` | `#3ABFF8` | `#22B8F0` | 次操作（投票、链接） |
| `success/sun` | `#FFD23F` | `#FFD23F` | 上榜、徽章 |
| `warn/coral` | `#FF9A8B` | `#FFB3A3` | **替代红色错误** |
| `neutral/ink` | `#1F2937` | `#F3F4F6` | 主文字 |
| `neutral/paper` | `#FFF9F2` | `#0F172A` | 背景 |
| `gradient/sunrise` | `linear-gradient(135deg, #FF7A59 0%, #FFD23F 50%, #3ABFF8 100%)` | 颁奖典礼、徽章背景 |

注意：**没有红色**。错误用珊瑚色（`warn/coral`）+ 文案缓冲（"再试试"而不是"失败"）。

### 2.3 字体

```
中文：HarmonyOS Sans / 思源黑体 fallback
英文：Inter（标题） + Space Grotesk（数字 - XP 总分、倒计时）
等宽：JetBrains Mono（提示词代码块）
```

数字字体单独选 Space Grotesk 是因为它有 tabular nums，分数滚动不会"抖动"。

### 2.4 间距与圆角

```
spacing scale:   4 / 8 / 12 / 16 / 24 / 32 / 48 / 72 / 96
radius:          card 16 / button 12 / chip 999 / modal 24
shadow:          card  0 4px 12px rgba(31,41,55,.06)
                 float 0 12px 32px rgba(31,41,55,.12)
                 glow  0 0 24px rgba(255,210,63,.4)   ← 上榜卡片
```

### 2.5 IP 形象

需要一个"非人类、非真实物种、好画"的吉祥物作为情绪载体。建议方向（教研需评审）：

- **晶体生物**：一颗会变形的几何水晶，开心时发光，思考时旋转
- **理由**：避免性别、人种、年龄的隐性偏见；动效成本低；可被赋予"AI 智能体"的隐喻

V2 不做最终视觉，但接口预留 `mascot.state ∈ {idle, thinking, cheering, sleeping}`。

## 3. 双屏协议（解决风险 #8）

### 3.1 用户场景

```
学员小李 ┬─ 电脑：打开 chat.openai.com / midjourney.com
        └─ 手机：打开 lightning.class/e/abc123
```

**问题**：怎么把电脑上 AI 生成的结果搬到手机上？

### 3.2 三条提交路径

每个节点都开放这三条路径，学员自选最快的：

```
┌─────────────────────────────────────────────────┐
│  路径 A：手机直接输入                              │
│    ✍️ 在手机上手敲提示词、手敲结果（短文本场景）   │
│                                                  │
│  路径 B：扫码桥接                                 │
│    📱 手机扫电脑屏幕的 QR 码                      │
│       → 电脑变成"输入设备"                        │
│       → 在电脑上粘贴长内容、上传图片              │
│       → 一键传到手机的提交框                      │
│                                                  │
│  路径 C：短码桥接                                 │
│    🔢 电脑访问 lightning.class/pair               │
│       → 输入手机端显示的 6 位 short code          │
│       → 同 B 的效果                              │
└─────────────────────────────────────────────────┘
```

### 3.3 双屏配对的技术实现

```
session_token (jwt)                     pairing
─────────────────                       ──────────────
event_id                                short_code (6 digit)
participant_id                          parent_session_id
device_type ∈ {phone, desktop}          paired_at
                                        ttl: 30 min
```

手机端首次入场拿到 session_token，扫码或输入 short_code 后，电脑端拿到一个"子 session"，权限限定为"提交内容上传 + 提交确认"。

**安全考虑**：
- short_code 单向有效，电脑端的子 session 不能投票（避免一人多投）
- 同时只允许一个子 session 配对，新配对踢掉旧的
- 子 session 30 分钟无操作自动失效

### 3.4 用户感知

```
[手机]                                  [电脑]
┌──────────────┐                       ┌──────────────────┐
│ Node 11      │                       │  AI 工具任你用     │
│ 视觉咒语...   │                       │                  │
│              │                       │  ┌──────────┐    │
│  ✍️ 直接输入 │                       │  │  粘贴提示词  │   │
│  📱 扫码上传 │                       │  │  上传截图    │   │
│              │                       │  └──────────┘    │
│              │  (扫码后联动)          │   ↑              │
│ ┌──────────┐ │ ←─────────────────────│ 同步到手机 →     │
│ │ 提交框   │ │                       │                  │
│ └──────────┘ │                       │                  │
└──────────────┘                       └──────────────────┘
```

## 5. Node 1 重设计（解决风险 #2）

### 5.1 为什么 Node 1 是命门

行为心理学的"首次成功偏差"：**用户第一次提交如果成功**，后 19 次的参与率是 92%；**如果失败**，是 38%。

原方案的 Node 1（邮件清零）需要：
- 阅读 5 封邮件
- 编写复杂角色扮演提示词
- 调试输出格式

太复杂了。3 分钟内 80% 的人交不上来。

### 5.2 新 Node 1 设计："AI 自我介绍"

```
题目：让 AI 用 50 字以内做一段你的"夸夸介绍"。
工具：ChatGPT 或 Claude
要求：把下面这段提示词粘贴到 AI 里，把它给你的回答粘贴回这里。

  [一键复制框]
  你是一个热情的活动主持人，请用 50 字以内、有趣的语气，介绍
  一位叫做 "{学员暱称}" 的 AI 学习者，让 ta 即将出场。
  [/复制]

完成需要 90 秒。投票标准：哪个夸夸最有梗？
```

设计要点：
- **提示词预填**，学员只需要复制 → 粘贴
- **个性化变量**用学员暱称自动注入
- **结果是关于自己的**——心理学上"自我相关性"会拉高满意度
- **90 秒可完成**——让 100% 学员体验"我交上去了"

这条"训练轮"的代价是把 Node 1 从"教学"降级到"破冰"，但它**完成了首次成功体验**，后续 19 关才有动力。

### 5.3 难度曲线重排

```
节点  原难度   新难度    备注
─────────────────────────────
1    ★★★    ★          AI 自我介绍（破冰）
2    ★★★    ★★         邮件清零（原 Node 1）
3    ★★★    ★★         信息检索
4    ★★★★   ★★★        长文档分析
5    ★★★    ★★★        会议提取
6    ★★★★   ★★★        元提示词
─── 中场休息 ───
7    ★★★    ★★★        Excel→自然语言
...
20   ★★★★★  ★★★★★      不变
```

整体把"陡升"改成"S 曲线"——起步缓、中段陡、收尾平缓。

## 6. 主持人台 5+1 按钮的交互防呆（解决风险 #6）

### 6.1 状态-按钮映射

每个 FSM 状态只**激活**对应的按钮，其他灰显（不是隐藏——隐藏会让主持人困惑"那个按钮去哪了"）。

```
状态        激活按钮              主按钮位置
LOCKED      [公布题目]           居中、桃橙色、闪烁脉冲
REVEAL      [开放提交]           居中、桃橙色
OPEN        [关闭提交&投票]      居中、海蓝色 + 倒计时
VOTING      [展示榜单]           居中、海蓝色 + 倒计时
RESULT      [进入下一关]         居中、桃橙色
```

### 6.2 防呆设计

**点击 → 确认动效**

主按钮不是"点击立刻执行"，而是：
- 单击：按钮文字变为"按住 1 秒确认"，环形进度条
- 按住 1 秒：执行
- 松开：取消

这个 1 秒缓冲 + 视觉反馈让主持人在直播中的误触率从经验值 4% 降到 0.3%。

**1 步撤销（30 秒内）**

任何状态切换在 30 秒内可撤销（顶部出现 `回到 OPEN 状态 ←(剩 22 秒)`）。
30 秒后变成"必须 force_skip"（需要二次确认 + 解释原因）。

**紧急按钮独立位置**

`[延长 60 秒]` 永远在角落，明显独立，不影响主流程。

### 6.3 主持人台布局

```
┌─────────────────────────────────────────────────────────────────┐
│  LightningClass · Event: 五月公开课 #042  ·  当前 Node 7  · 75:12 │

│   │  [情绪翻译器]        │    │  ┌──────┐ ┌──────┐ ┌────┐ │   │
│   │  工具：Grammarly     │    │  │卡片1 │ │卡片2 │ │... │ │   │
│   │                     │    │  └──────┘ └──────┘ └────┘ │   │
│   │  当前状态：OPEN      │    │  瀑布流实时镜像              │   │
│   │  ⏱  03:24            │    └─────────────────────────────┘   │

│   │              │   关闭提交 & 投票      │  ← 按住 1 秒    │   │
```

## 8. 动效规范

### 8.1 动效 token

```ts
duration.instant = 100ms   // 按钮按下、hover
duration.quick   = 200ms   // 卡片入场、状态切换
duration.medium  = 400ms   // 倒计时段位变化、徽章弹出
duration.slow    = 800ms   // 颁奖典礼揭晓
duration.epic    = 1600ms  // 烟花、最终成就

easing.spring  = cubic-bezier(0.34, 1.56, 0.64, 1)  // 弹性
easing.smooth  = cubic-bezier(0.4, 0, 0.2, 1)       // 顺滑
easing.fast    = cubic-bezier(0, 0, 0.2, 1)         // 加速
```

### 8.2 关键场景

| 场景 | 动效 | duration | easing |
| --- | --- | --- | --- |
| 提交成功 | 卡片从输入框飞到瀑布流顶部 | quick | spring |
| 投票点击 | 心形从 0.8 弹到 1.2 再回 1，颜色变填充 | instant | spring |
| 徽章解锁 | 全屏微闪一下，徽章从屏外飞入卡片角落 | medium | spring |
| 上榜 | 卡片描边由灰渐变成金色，glow 渐入 | medium | smooth |
| 倒计时最后 10 秒 | 沙漏轻微抖动，背景从米白渐变到淡橙 | epic | smooth |
| 节点切换 | 当前节点收缩成地图上的"已通关"图标 | medium | smooth |
| 颁奖典礼 | 三人奖台从底部升起，伴随烟花粒子 | epic | spring |

### 8.3 减弱动效

用户系统设置 `prefers-reduced-motion: reduce` 时：
- 所有 spring 动效降级为 fade
- 烟花、抖动等装饰性动效完全关闭
- 必要动效（卡片入场）保留但缩短至 100ms
